# 旅すご 仕様書（v5）

道端の構造物になりきって写真を撮る、位置情報すごろくゲームの仕様書。
本書はCloudflare版（Pages Functions + D1）の現行実装を正とする。最終更新: 2026-08-07。

---

## 1. 目的・コンセプト

観光名所ではなく、マンホール・バス停・消火栓・彫刻といった「道端のどうでもいいもの」を旅の主役にする。オープンデータから盤面を自動生成し、サイコロを振って実際に歩き、着いた場所の被写体と同じポーズで写真を撮る。**役に立たないものを思い出に変える**ことがねらい。

大学の授業「デジタルメディア制作」課題（テーマ: 役に立たないものを作る）。

## 2. ゲームの流れ

1. プロフィールでニックネーム（1〜10文字）とアイコン絵文字を決める
2. マップで中心地点・半径・マス数（2〜30）を選び、盤面を自動生成 → 部屋作成（6桁コード発行）。起動時に現在地を取得し、**中心マーカーは現在地に初期配置**（地図タップやスライダーで調整可。位置情報を拒否した場合は既定地点）
3. 部屋コードまたは招待リンク（`?join=CODE`）で仲間が参加（1部屋最大8人）
4. サイコロを振り、出目のぶんルート上を1マスずつ進む（進行状況はサーバに保存＝リロードしても位置は保持）
5. 目的地でGPS到着判定 → 被写体と同じポーズで撮影 → 送信
6. **アップロード時にAIが自動採点**（星1〜5＋電柱の写り込みを判定）。得点が即反映される
7. 採点タブで自分・みんなの写真とAI判定を閲覧。他人の写真には**絵文字リアクション**を送れる（得点には無関係）
8. ゴールで「そっくり大賞」「なにこれ大賞」を表彰。自分の写真は「旅すごのしおり」（アルバムPNG）として保存でき、大賞も一緒に載る

## 4. 採点（AI判定）

### 4.1 方式
- 写真アップロード（`POST /api/rooms/{code}/photos`）時に、Cloudflare Workers AI のビジョンモデル **`@cf/meta/llama-3.2-11b-vision-instruct`** を同期呼び出しする。
- AIは「その被写体カテゴリのモノマネがどれだけ似ているか」を判定し、次のJSONを返す:
  - `stars`: 1〜5の整数（似ているほど高い）
  - `pole`: 電柱が写っていれば true
  - `comment`: 子ども向けの短い日本語講評（40文字以内）
- 結果は `photos.ai_stars / ai_pole / ai_comment / ai_status` に保存する。`ai_status` は `pending`（判定前）/ `done`（成功）/ `failed`（失敗）。

### 4.2 得点計算（仕様）
```
得点 = 基礎点 × AIの星(1〜5) + 電柱ボーナス(電柱ありなら +5)
```
- プレイヤーの総合得点は、その人の全写真の得点合計。
- 電柱ボーナスの有無は**AIが判定する**（人の申告ではない）。「判定をAIに全任せする」方針に基づく。

### 4.3 フォールバックと堅牢性
- AI呼び出しが失敗・タイムアウト（20秒）しても、**写真は必ず保存済み**。星3・`ai_status=failed` で採点を続行し、アップロード自体は失敗させない。
- AIが返す構造化レスポンスは、文字列・パース済みオブジェクトのどちらの形式でも受け取れるようにする。JSONが壊れていれば本文から星を推定し、最終的に星3へフォールバックする。
- Metaライセンス未同意（エラー5016）の場合もフォールバックとなるため、本命モデルを使うにはアカウントで一度ライセンス同意が必要（本番アカウントでは同意済み・2026-08-07）。

### 4.4 モデルとプロンプトの詳細

- **モデル**: Meta Llama 3.2（11B）のビジョン版 `@cf/meta/llama-3.2-11b-vision-instruct`。画像＋テキストを同時に理解するマルチモーダルモデルで、Cloudflare Workers AI 上で動く。別APIキーは不要（`[ai]` バインディング経由）。
- **入力**:
  - 画像バイト列（アップロードされた写真をそのまま渡す）。
  - プロンプト = 審査員ロール＋被写体カテゴリの日本語ラベル（`manhole→マンホール` 等）＋「JSON1行だけを出力」という指示＋星の目安（5=そっくり〜1=あまり似ていない）。
  - パラメータ: `temperature 0.3`（判定のブレを抑える）、`max_tokens 200`、20秒タイムアウト。
- **出力の期待形式**: `{"stars":1〜5, "pole":true/false, "comment":"短い日本語講評"}`
- **レスポンス解析（頑健化）**:
  - このモデルは `response` を「文字列」でも「パース済みオブジェクト」でも返すため、両方に対応する。
  - 正規表現で最初の `{…}` を抜き出して `JSON.parse`。`stars` は1〜5にクランプ、壊れていれば本文中の最初の `1〜5` を拾い、それも無ければ `3`。
  - `pole` は `true/1/"true"`、JSONが壊れていれば本文に「電柱／pole」が含まれるかで判定。
  - `comment` は40文字に切り詰め、空なら既定文言。
- **得点への反映**: 解析結果の `stars`・`pole` を `photos` テーブルに保存し、`4.2` の式で得点化する。

## 5. 絵文字リアクション（得点に影響しない）

- 旧「人による相互採点」は廃止し、代わりに**得点に一切影響しない絵文字リアクション**を提供する（`POST /api/photos/{id}/reactions`）。
- 使える絵文字: 😆 わらった / 👏 そっくり / 😮 びっくり / ❤️ すき。
- 1人が1写真につき1つ。同じ絵文字を再送すると取り消し、別の絵文字を送ると差し替え。
- **自分の写真にはリアクションできない**（403）。許可外の絵文字は拒否（400）。
- 表彰の集計に使う（得点には加算しない）:
  - 🏆 **そっくり大賞** = 👏 が最多の写真
  - 🤔 **なにこれ大賞** = 😆 が最多の写真
  - リアクションが1つも無いときのみ、AIの星で代替（最高＝そっくり大賞 / 最低＝なにこれ大賞）。

## 6. ネット公開ギャラリー（部屋の得点とは完全に別）

- 撮影者は写真を任意でネット公開できる（顔を隠す編集を経てから公開）。
- 公開写真には世間が星投票できる（1ブラウザ1票）。**この投票は部屋の得点に一切影響しない。**
- 通報が3件たまった写真は自動的に非公開になる。
- 公開を取り下げると、公開用画像と投票が即座に削除される。

## 7. 絶対に変えてはいけない仕様

移植・改修の過程でこれらが壊れていないことを、`test_api_cf.sh`（Cloudflare版）/ `test_api.sh`（Apache版）で必ず確認する。

1. **自分の写真には自分でリアクションできない**（403）
2. **得点 = 基礎点 × AIの星 + 電柱ボーナス（電柱ありで +5、電柱もAIが判定）**
3. **ネット投票・リアクションは部屋の得点に一切影響しない**（完全に別集計）
4. **ネット公開できるのは撮影した本人だけ**（他人は403）
5. **公開を取り下げると、公開用画像と投票が即座に削除される**
6. **部屋の写真は、その部屋のメンバーしか見られない**（トークン検証。なければ403）
7. 部屋は作成から30日で自動削除
8. 部屋コードは紛らわしい文字（I/L/O/0/1）を除いた6桁英数
9. ニックネームは1〜10文字、1部屋あたり最大8人
10. 使えるリアクション絵文字は許可リストのみ（範囲外は400）

## 8. 技術スタック

- **フロント**: 静的HTML/CSS/JS（`index.html`, `assets/`）。地図は Leaflet + オープンデータの `data/spots.geojson`。PWA（Service Worker `sw.js`、`VERSION` を上げると即更新）。
- **バックエンド**: Cloudflare Pages Functions（`functions/api/[[path]].js` に集約）。
- **DB**: Cloudflare D1（SQLite）。**写真はファイルではなくD1のBLOBに保存**（1枚あたり長辺1000px・JPEG品質0.75へクライアント側で縮小）。
- **AI**: Cloudflare Workers AI（`wrangler.toml` の `[ai] binding = "AI"`）。
- **徒歩経路**: OpenRouteService をサーバ側でプロキシ（APIキーはフロントに出さない）。
- **マイグレーション**: `migrations/0001_init.sql`（基本スキーマ）/ `0002_ai_judging.sql`（AI採点列）/ `0003_reactions.sql`（リアクション）。

## 10. デプロイ手順（Cloudflare）

1. `npm run db:migrate:remote` … リモートD1へ 0001〜0003 を適用
2. Cloudflare Pages プロジェクトで **Workers AI を有効化**
3. Metaライセンス同意（本命モデルを使う場合。アカウントで一度だけ）
4. `npx wrangler pages deploy .` でデプロイ
5. 本番で部屋作成→写真アップロードし、`ai_status=done`・得点反映を確認

## 11. 音声（BGM・効果音）

- **効果音**: Web Audio APIで合成（外部ファイル不要・オフライン可）。サイコロ・到着・シャッター・スター・勝利・ボタンクリック等。マスターゲインで全体を底上げ。🔊ボタンでオン/オフ（`monomaneMuted` に保存）。
- **BGM**: チームメイト制作の楽曲 `assets/audio/bgm.mp3` をループ再生。🎵ボタンでオン/オフ（`monomaneBgm` に保存し、前回オンなら次の操作で自動復帰）。
- **ダッキング**: 効果音が鳴る瞬間だけBGMをすっと下げ、約0.3〜0.4秒かけて基準音量へ戻す。効果音がBGMに埋もれないようにするため。
- Service Worker は `.mp3` を素通し（`<audio>` のRangeリクエストがCache APIと相性が悪いため）。

## 12. アルバム（旅すごのしおり）

- 自分の写真をまとめた**1枚のPNG画像**をクライアント側（Canvas）で生成し、保存/共有できる（スマホは共有シート経由で写真アプリへ、PCはダウンロード）。
- ヘッダー（アプリ名・プレイヤー名・総合得点・日付）＋**大賞バンド**（そっくり大賞・なにこれ大賞）＋自分の写真グリッド（被写体名・星・得点）で構成。
- 大賞は部屋全体から算出し、結果ダイアログと同じ `computeAwards()` を共有（👏/😆最多、無ければAIの星でフォールバック）。写真が2枚未満なら大賞バンドは省略。
- 結果ダイアログの「アルバムを作る」／プロフィールタブの「🖼️ アルバムを作る」から生成。
